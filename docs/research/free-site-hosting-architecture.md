# Zero-cost hosting options for the public catalog

**Research date:** 2026-11-03  
**Scope:** Public Vietnamese product/catalog site, public GitHub source repository, one authenticated content editor, Sanity public published content, designed page sections, $0 recurring service spend, SEO, and near-immediate publish. This compares hosting and delivery choices; it does not select one.

**Status.** The report is local and uncommitted because this repository has no commits. No research branch was pushed. The final hosting/rendering choice remains open.

## Summary

There are two strong Cloudflare Pages + Sanity patterns, with different trade-offs:

1. **Static generation plus Sanity deploy hook:** render complete HTML at build time for strong crawlability, then have Sanity call a Cloudflare Pages deploy hook after publish. This is operationally simple and avoids runtime page-rendering functions, but a publish is visible only after build/deploy completes. Cloudflare Free currently allows 500 builds/month, one at a time, and a 20-minute build timeout.
2. **Static shell plus published-content API reads:** deploy the designed HTML/CSS/JS to Pages and read Sanity's public published dataset in the browser, or use a Pages Function/server renderer for selected pages. Browser/API rendering avoids a site rebuild and can show edits on the next request, but pure client rendering can weaken SEO and needs loading/error behavior. A server-rendered Pages Function can return crawlable HTML, with a 100,000-request/day Free Workers quota for function invocations. Pages static asset requests themselves are free and unlimited.

GitHub Pages is free for public repositories and supports static site builds, but GitHub expressly says Pages is not intended or allowed as free hosting for an online business, e-commerce site, or site primarily directed at facilitating commercial transactions. A product catalog operated to generate sales may fall into that category; whether a non-transactional informational catalog does is not settled by the documentation. That makes GitHub Pages a terms-risk option for this business-facing use case.

Sanity Free has public-only datasets and enough general capacity for a small catalog (20 seats, 10,000 documents, 1 million API CDN requests/month, 250,000 API requests/month, 100 GB assets and bandwidth in the current pricing table). It has hard caps: crossing a quota can block public API delivery until the monthly reset or upgrade. One user can publish on Free as an Administrator, but Free does **not** provide the narrower Editor role; that role requires Growth. Confirm whether broad project-admin permissions are acceptable for the single editor.

## Options and trade-offs

| Option | Publish path and freshness | SEO and implementation | Free-tier / terms fit |
|---|---|---|---|
| **GitHub Pages + Sanity API reads** | Publish in Sanity; no repository commit/rebuild required if the website reads Sanity live. Sanity's uncached API returns freshest data; API CDN is designed for frontend reads and has cache/invalidation behavior. | Can retain the current designed frontend. For SEO, pre-render content or render it server-side; browser-only rendering puts content behind JavaScript execution. | Public repo qualifies for Pages Free. But GitHub Pages' commercial-use restriction makes it a poor fit if the catalog promotes a sales business or facilitates transactions. |
| **Cloudflare Pages static build + Sanity deploy hook** | Sanity publish webhook POSTs the unique Pages deploy-hook URL; Pages rebuilds the connected Git branch using current Sanity data. Near-immediate means after the build, not instant on publish. | Pre-render each designed page into HTML at build time. Strong crawler-accessible output, static delivery and no per-request Function. SEO metadata and canonical URLs still need to be generated by the site. | Pages Free: 500 builds/month, 1 concurrent build, 20-minute timeout, up to 20,000 files, 25 MiB per file. Deploy hooks are explicitly documented for Sanity. Hook URL is a secret and can trigger a build. |
| **Cloudflare Pages static shell + browser Sanity API** | Publish in Sanity; visitors query public published documents directly. No build hook required for content changes. Sanity documents automatic CDN invalidation after publishing, but API CDN can serve cached results and is not a strict real-time guarantee. | Lowest hosting complexity. Pure client rendering risks SEO visibility and page-load flashes; pre-render important SEO landing/product pages or choose server rendering if SEO is material. | Pages static asset requests are free/unlimited. Sanity Free API CDN and bandwidth quotas remain the content-delivery ceiling. |
| **Cloudflare Pages + Pages Functions for SSR/API proxy** | Function reads public Sanity content on each request (use API CDN for cacheable published reads) and returns HTML; publish does not require a Pages build. | Allows server-rendered HTML and server-side metadata while keeping static assets on Pages. More code and runtime behavior to maintain. No write token should be placed in public/browser code. | Pages Function requests count against Workers Free's combined 100,000 requests/day quota and reset daily at 00:00 UTC. Static asset requests do not count. Exceeding the Workers quota can return error 1027. |

All options preserve the public repository requirement; source visibility and hosting are separate. Do not put Sanity write credentials or a Cloudflare deploy-hook URL in the public repository. A deploy hook is a bearer secret in its URL: configure it in Sanity's webhook UI and restrict the event to the production dataset and publish/unpublish events.

## Verified provider details

### GitHub Pages

- GitHub Pages is a static host that serves HTML, CSS and JavaScript from a repository, with optional build processing. GitHub Free supports Pages for public repositories. A custom domain is supported.
- The published-site ceiling is 1 GB, with a soft 100 GB/month bandwidth limit and a soft 10 builds/hour limit (the latter does not apply to a custom GitHub Actions publish workflow); deploys time out after 10 minutes.
- **Terms constraint:** GitHub says Pages is not intended for or allowed as free hosting for an online business, e-commerce site, or another website primarily directed at facilitating commercial transactions or providing commercial SaaS. The docs do not define where a product catalog with contact links but no checkout falls. Treat suitability as unresolved and obtain a provider interpretation if choosing Pages for a commercial catalog.

Sources: [What is GitHub Pages?](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [GitHub Pages limits and commercial-use restriction](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).

### Cloudflare Pages and Functions

- Cloudflare Pages supports Git-connected builds, static asset delivery and Pages Functions. Free Pages currently permits 500 builds/month, one build at a time, 20-minute timeout, 20,000 files per site, and 25 MiB max per asset; the current docs list 100 custom domains and unlimited active preview deployments. This project needs only one domain and should be well under the build/file ceilings unless every edit causes unusually frequent rebuilds.
- Requests to static assets are free and unlimited on both Free and paid plans. Pages Function requests are billed against Workers plan quotas; on Workers Free the daily allowance is 100,000 requests shared with other Workers usage in the account, resetting at midnight UTC. This is not equivalent to a 100,000-per-day allowance reserved exclusively for this site.
- Cloudflare Pages Deploy Hooks provide a unique URL that accepts HTTP POST to start a deployment of a selected branch. Cloudflare documents Sanity as an integration: enter the URL in the Sanity project's Webhooks settings, optionally limit it to the production dataset. Anyone holding that URL can trigger builds; keep it secret and rotate it if exposed. Each call starts a build (subject to rate limits); Cloudflare documents 10 builds/minute per Worker and 100/minute per account for deploy hooks.
- Cloudflare's official docs describe Free plan availability and limits, but this research did not locate a Pages-specific terms clause expressly confirming/denying use for a commercial catalog. No such prohibition was found in the reviewed Pages docs; this is not a legal determination of all applicable Cloudflare terms.

Sources: [Pages overview](https://developers.cloudflare.com/pages/), [Pages limits](https://developers.cloudflare.com/pages/platform/limits/), [Pages Functions pricing](https://developers.cloudflare.com/pages/functions/pricing/), [Workers limits](https://developers.cloudflare.com/workers/platform/limits/), [Pages Deploy Hooks](https://developers.cloudflare.com/pages/configuration/deploy-hooks/).

### Sanity Free, access, freshness and quotas

- The Free pricing page lists 20 seats, two **public-only** datasets, 10,000 documents, two roles (Administrator and Viewer), 1 million API CDN requests/month, 250,000 direct API requests/month, 100 GB assets, 100 GB bandwidth/month, hosted Studio and free Studio hosting. Viewer seats are free. The current plan matrix does not include the Editor role on Free; Growth lists Editor and costs $15/seat/month.
- A Free-plan Administrator can read/write all datasets and manage project settings, so a single authenticated owner can edit/publish without paying, but with broader access than a scoped Editor. If “one authenticated editor” requires least-privilege Editor permissions, the listed Free plan does not meet that requirement.
- Published documents in a public dataset are visible to unauthenticated API requests. Drafts and release versions are not served to unauthenticated requests; they remain separate from published content until publish. This supports public read access with authenticated editorial access and no public write token.
- Sanity's uncached API is the freshest option. The API CDN is recommended for user-facing reads, supports published/raw perspectives, and automatically serves cached query results. Sanity states it prioritizes invalidation and returns the last cached result for up to two hours if Content Lake is unavailable; its docs do not promise a hard maximum publish-to-visibility latency. For a static build, query the uncached API at build time to get the latest content, then deploy.
- Free projects cannot pay overages. API, API CDN and bandwidth quotas reset monthly at 00:00 UTC; on hitting a cap, additional API/CDN calls fail (documented as HTTP 402) and public content can stop loading until reset/upgrading. The Studio remains usable. Documents include drafts as separate records, so heavy draft/version use counts toward the 10k ceiling.

Sources: [Sanity pricing](https://www.sanity.io/pricing), [roles](https://www.sanity.io/docs/user-guides/roles), [drafts and versions](https://www.sanity.io/docs/content-lake/drafts-and-versions), [authentication and tokens](https://www.sanity.io/docs/content-lake/http-auth), [API CDN and caching](https://www.sanity.io/docs/content-lake/api-cdn), [plans and quota behavior](https://www.sanity.io/docs/platform-management/plans-and-payments).

## Decision points for the product owner

- Is the catalog part of a commercial sales operation, and does “publish” mean visible on the next public request or visible after a static rebuild completes?
- Is one broad Sanity Administrator login acceptable on Free, or is a scoped Editor role required (which changes the cost comparison)?
- How important is HTML availability to search crawlers and social previews? If high, compare static rebuild-on-publish against SSR Functions; browser-only rendering is the simplest option but least certain for SEO.
- Does the expected audience fit within Sanity's Free hard quotas (especially 1M API CDN requests and 100 GB monthly bandwidth)? If exceeded, the site can stop receiving published content rather than accrue a small overage.

## Verification limits

- GitHub's documentation does not classify an informational product catalog without cart/checkout as allowed or prohibited; its stated commercial transaction rule leaves that edge case ambiguous.
- I did not find a Cloudflare Pages-specific official terms paragraph defining commercial catalog use. The pages documentation documents Free plan use and limits, but does not by itself establish a comprehensive legal permission.
- Sanity publishes no guaranteed cache invalidation SLA or exact maximum publish propagation time in the cited CDN documentation. “Near-immediate” via API is a design expectation, not a contractual guarantee. Static deploy-hook publishing necessarily waits for build/deploy completion.
