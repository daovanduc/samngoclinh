# Domain Docs

Before exploring, read the root `GLOSSARY.md`, or `GLOSSARY-MAP.md` if present and the relevant context glossaries it points to. Read relevant ADRs in `docs/adr/`. If these files do not exist, proceed silently; the domain-modeling skill creates them when concepts or decisions are resolved.

Use glossary terms in issue titles, refactor proposals, hypotheses, and test names. If a needed concept is missing, note the gap for domain modeling. Surface conflicts with existing ADRs rather than silently overriding them.

This repo uses a single-context layout: root `GLOSSARY.md` and `docs/adr/`.
